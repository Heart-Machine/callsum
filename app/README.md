# Приложение на C#

Вторая версия callsum: настольное приложение, которое можно раздать коллегам без Python
и ручной настройки OBS. План и принятые решения — в [docs/plan.md](../docs/plan.md).

Сейчас готовы этапы со второго по пятый: работа с OBS, окно приложения, настройки,
установщик с самообновлением. Библиотеки видеокарты и модель распознавания в установщик
не едут — они скачиваются при первом распознавании, и это видно в окне.

| Проект | Что это |
|---|---|
| `Callsum.App` | окно на WinUI 3: кнопка записи, таймер, список готовых записей, уведомления |
| `Callsum.Core` | связь с ядром обработки: команды и события строками JSON, чтение результатов |
| `Callsum.Obs` | клиент протокола obs-websocket 5 и настройка профиля под запись созвонов |
| `Callsum.ObsTool` | консольная утилита: проверить связь и прогнать запись до того, как появится окно |
| `Callsum.Obs.Tests` | тесты протокола и разбора настроек |

## Что нужно для сборки

.NET SDK 9. Ставится в профиль пользователя, без прав администратора:

```
Invoke-WebRequest https://dot.net/v1/dotnet-install.ps1 -OutFile dotnet-install.ps1
.\dotnet-install.ps1 -Channel 9.0 -InstallDir "$env:LOCALAPPDATA\Microsoft\dotnet"
```

Дальше:

```
dotnet build app\Callsum.sln
dotnet test app\Callsum.sln
```

## Запуск окна

```
dotnet run --project app\Callsum.App
```

Окно само подключается к OBS и запускает ядро обработки, найденное рядом с собой или
в папке `dist` проекта. После остановки записи файл уходит в ядро, а окно показывает ход
работы: подготовку дорожек, распознавание с долей выполнения и составление протокола.

Окно восстанавливает связь с OBS после обрыва. Кнопка начинает и
останавливает запись; пока OBS выполняет команду, кнопка занята — он переключает профиль
и закрывает файл не мгновенно. Заголовок окна показывает, идёт ли запись.

## Список записей и уведомления

Готовые записи перечислены в окне, свежие сверху; строка говорит, есть ли протокол или
пока только расшифровка. Нажатие на строку открывает протокол, кнопка «Папка» — папку
с файлами, кнопка «Заново» — пересобирает расшифровку и протокол с нуля. Исходную запись
для этого окно берёт из `transcript.json`, куда разбор записывает полный путь к ней;
если файла там больше нет, запись ищется по имени в папке записей. Чем открывать `.md`, решает настройка `[view] markdown_app` в `config.toml`:
запись понимается так же, как в первой версии — имя программы, путь к ней, команда
с подстановкой `{file}` или ссылка вида `obsidian://open?path={file}`.

Где лежат записи и результаты, окно не угадывает: пути хранятся в настройках ядра,
поэтому при запуске оно спрашивает у ядра проверку окружения и берёт их оттуда.

Когда обработка заканчивается, Windows показывает уведомление — созвон обрабатывается
минутами, и всё это время окно обычно свёрнуто. Уведомление подписано именем `callsum`:
имя берётся из регистрации приложения (`AppUserModelID`), а без неё в подписи оказалось бы
имя исполняемого файла — в первой версии там стояло «Python».

Журнал переехал в свёрнутый раздел внизу: он нужен, когда что-то пошло не так.

## Что мешает работе

Ядро проверяет окружение при запуске — FFmpeg, видеокарту, Ollama и модель протокола, —
но раньше его ответ читала только вкладка «О программе». Про молчащую Ollama человек узнавал
через час, когда протокол не собрался, а про отсутствующий FFmpeg — когда пропала первая
запись.

Теперь замечания появляются плашками над кнопкой записи, и каждое говорит, что делать:
поставить FFmpeg такой-то командой, запустить Ollama, загрузить модель, выбрать другую папку.
Закрыть плашку нельзя — причина от этого не исчезнет; вместо этого под ними есть «Проверить
ещё раз»: Ollama запускают и модель докачивают, не перезапуская программу.

Два замечания сделаны намеренно мягкими. Пока не скачаны библиотеки видеокарты, окно говорит
не «что-то не так», а «первое распознавание будет долгим»: это нормальное состояние новой
установки. А про расчёт на процессоре говорится последствием — «в десятки раз дольше», —
потому что причина может быть и в отсутствии видеокарты, и в выбранном вручную устройстве.

О молчащей Ollama окно молчит, если протокол выключен в настройках: жалоба на то, чего
не просили, приучает не читать предупреждения.

## Настройка OBS

Записывает созвон OBS, но записывает он так, как настроен: одной дорожкой, в своём формате
и в свою папку. Программе нужны две дорожки в mkv и своя папка, поэтому у неё есть профиль
и коллекция сцен `callsum` — и заводит их само приложение.

Когда OBS подключился, окно спрашивает у него, есть ли то и другое. Если нет — наверху
появляется ссылка «Настроить OBS» и строка в журнале о том, что запись пойдёт с чужими
настройками. Нажатие заводит профиль, коллекцию сцен, разводит микрофон и звук системы
по дорожкам 1 и 2, задаёт формат, папку и маленький холст 640×360: картинка в протокол
не попадает, а час такой записи занимает единицы мегабайт.

Раньше это умела только консольная утилита `Callsum.ObsTool`, которой у коллеги нет.
Коллега получал OBS без профиля — то есть запись, из которой ничего не соберётся, —
и узнавал об этом после созвона.

Ход работы уходит в журнал построчно: настройка занимает около полуминуты, потому что OBS
нужно время перестроить микшер и перечитать профиль. Чужой профиль при этом не трогается —
о том, какой был, приложение говорит в первой же строке.

Кнопка «Настроить OBS заново» есть и в настройках, на вкладке «Запись»: ею чинят OBS,
если профиль удалили или испортили руками. Настраивает она по **сохранённым** значениям,
а не по набранным в форме: иначе OBS начал бы писать туда, где программа записи не ищет.

Что приложение не делает само — websocket-сервер в OBS. Это общая настройка OBS, а не
наш профиль, и включается она галочкой в «Сервис» → «Настройки сервера WebSocket».
Пока её нет, окно так и говорит, с точным путём до галочки.

## Настройки

Ссылка «Настройки» в правом верхнем углу открывает окно с вкладками: «Папки», «Запись»,
«Распознавание», «Говорящие», «Протокол» и «О программе». В нём есть всё, что лежит
в `config.toml`, — открывать файл руками больше незачем.

Вкладки собраны по делу, а не по разделам файла. Пауза, по которой длинная реплика режется
на части, стоит рядом с паузой, по которой соседние реплики склеивают, — хотя в файле они
лежат в разных разделах. Редкое — ширина поиска, размер куска для протокола, адрес и порт
OBS — убрано под «Дополнительно»: на виду остаётся то, что меняют.

Под полями подписано, что стоит в них по умолчанию. Числа набираются числовыми полями,
переключатели — переключателями, а «на чём считать» и «точность вычислений» выбираются из
списка: вписать в них опечатку больше нельзя. Модель распознавания выбирается из списка
известных, модель протокола — из тех, что уже загружены в Ollama: их список окно спрашивает
у неё через ядро, когда открывают вкладку. Вписать своё имя по-прежнему можно.

Файл настроек один — тот самый `config.toml`, который правят руками, — и владеет им ядро:
окно спрашивает значения командой `settings` и возвращает изменения командой `settings_set`.
Второго хранилища у приложения нет, поэтому расходиться нечему, а файл остаётся с
комментариями: ядро правит в нём отдельные значения, а не переписывает целиком.

Отправляются только изменённые поля. Если тем временем кто-то поправил файл руками, его
правки остаются на месте — окно не возвращает обратно всё, что прочитало при открытии.

Пустое значение там, где оно ничего не значит (папка, модель), не сохраняется: окно скажет,
какое поле нельзя оставлять пустым, и переключится на вкладку, где это поле стоит, — иначе
сообщение относилось бы к чему-то невидимому. А пустой язык и пустая программа для markdown осмысленны —
это «определять самому» и «чем открывает Windows».

Папка записей — единственная настройка, которая живёт в двух местах сразу: программа по ней
ищет записи, а OBS по своей пишет их. Поэтому при сохранении приложение задаёт её и OBS,
а при запуске сверяет обе и подтягивает при расхождении. Чужой профиль OBS не трогается:
если открыт не `callsum`, окно скажет об этом и отложит правку до возвращения в наш профиль.

Папки хранятся полными путями. Относительный путь считается от того места, откуда запущено
ядро, и в разных руках означает разные папки, а в окне «out» вообще ничего не говорит о том,
где искать протоколы. Поэтому новый `config.toml` создаётся уже с полными путями, окно
показывает их полностью, а относительный путь при сохранении не принимает. Под каждым полем
подписано, куда программа сложила бы всё сама, — видно, от чего отказываешься, выбирая свою
папку. Файл, в котором путь записан относительно, продолжает работать: при первом сохранении
из окна он превращается в полный.

### Устройства записи

Микрофон и звук системы выбираются там же, но живут они не в `config.toml`, а в коллекции
сцен OBS — вместе с источниками, которым принадлежат. Список даёт сам OBS: те же устройства
и в том же порядке, что в окне свойств источника. Недоступные (отключённая гарнитура)
в список не попадают — записать с них нечего.

Значение «По умолчанию» означает то устройство, которое выбрано в Windows. Это удобно, пока
их не несколько: у одной машины в списке оказались микрофон гарнитуры, микрофон веб-камеры
и блютус-гарнитура, и «по умолчанию» указывало не на тот, в который говорят, — запись
микрофонной дорожки выходила пустой. Поэтому устройство лучше выбрать явно.

Источники существуют в коллекции сцен `callsum`. Если в OBS открыта другая коллекция, окно
так и скажет: переключать её втихую оно не станет — это меняет то, что человек видит в OBS
прямо сейчас.

### О программе

Последняя вкладка отвечает на вопросы «какая это версия», «почему не работает» и «куда оно
всё скачало»: версии приложения и ядра, на чём считает распознавание, отвечает ли Ollama,
на месте ли ffmpeg и библиотеки видеокарты, пути к файлу настроек, моделям и библиотекам —
с кнопкой «Открыть папку» у каждого. Данные приходят из проверки окружения (`doctor`),
поэтому они настоящие на момент открытия вкладки, а не записаны в приложение.

Там же кнопка «Проверить обновление». Раньше об обновлении можно было узнать, только если
оно само нашлось при запуске, а на вопрос «стоит ли у меня последняя версия» ответить было
нечем.

Приложение собирается **самодостаточным**: Windows App SDK едет внутри него. Иначе
неупакованное приложение WinUI требует установленной на машину среды выполнения, а её
установка просит администратора — то, чего у коллег может не быть.

## Установщик и обновления

```
packaging\build-core.cmd
packaging\build-app.cmd
```

Первая команда собирает ядро, вторая — установщик через [Velopack](https://velopack.io):
`dist\releases\callsum-win-Setup.exe` (около 190 МБ), портативный архив и пакет для
обновлений. Один раз нужно поставить упаковщик: `dotnet tool install -g vpk`.

Установщик кладёт приложение в `%LOCALAPPDATA%\callsum` — без прав администратора,
без MSIX и без сертификата. Ядро едет внутри, в подпапке `core`: именно там приложение
ищет его рядом с собой. Версия берётся из `callsum/__init__.py` — одна на ядро и на
приложение, чтобы в релизе нельзя было перепутать, что с чем совместимо.

### Выпуск версии

```
packaging\set-version.ps1 1.1.0
```

Версия живёт в двух местах: в `callsum/__init__.py`, откуда её берёт сборка установщика,
и в `Callsum.App.csproj`, откуда её читает вкладка «О программе» при сборке из исходников.
Команда меняет обе сразу — разойдись они, окно называло бы не ту версию, которую поставили.

Номер отвечает на вопрос, нужно ли что-то делать руками: патч — исправления, минор —
заметное новое в окне, мажор — обновление, после которого коллеге придётся что-то сделать
(перенести папку, скачать другую модель). Понизить номер команда не даёт: Velopack не умеет
возвращаться назад, а выпущенный номер уже не переиспользовать.

Дальше — слияние, тег и сборка:

```
git switch main; git pull
git tag -a v1.1.0 -m "callsum 1.1.0"
git push origin v1.1.0
packaginguild-core.cmd
packaginguild-app.cmd
```

Предрелиз (`1.1.0-rc.1`) помечается на GitHub как pre-release: обновления приложение ищет
только среди обычных релизов, поэтому такой сборкой можно обкатать изменение на себе,
не раздав его коллегам.

Обновляется приложение само: при запуске оно спрашивает у GitHub, нет ли версии новее,
молча скачивает её и показывает ссылку «Обновить до …». Перезапуск — по нажатию: посреди
записи перезапускаться нельзя, и во время записи ссылка честно отвечает, что подождёт.

Две вещи, на которые ушло время и которые легко повторить:

- **Пакуется вывод обычной сборки, а не `dotnet publish`.** Публикация неупакованного
  приложения WinUI не переносит скомпилированный XAML (`.xbf`) и таблицу ресурсов
  (`.pri`) — собранное из неё приложение закрывается сразу после запуска, без окна,
  без ошибки и без записи в журнале Windows.
- **Скачанное лежит не в папке программы.** `%LOCALAPPDATA%\callsum` принадлежит
  установщику, и при установке он её очищает: первая же проверка унесла оттуда два
  гигабайта скачанных библиотек CUDA. Поэтому они живут в `%LOCALAPPDATA%\callsum-data`.

## Утилита для проверки

```
dotnet run --project app\Callsum.ObsTool -- doctor
```

| Команда | Что делает |
|---|---|
| `doctor` | подключается к OBS и показывает профиль, коллекцию сцен, папку записи и источники звука |
| `setup <папка>` | создаёт профиль и коллекцию сцен `callsum`, разводит звук по дорожкам, задаёт формат записи |
| `start` / `stop` | начинает и останавливает запись; `stop` печатает путь к файлу |
| `watch` | ждёт событий записи из OBS — в том числе начатой вручную или горячей клавишей |

Пароль к websocket утилита берёт из настроек самого OBS, вводить его никуда не нужно.

## Как устроен клиент

`ObsClient` разбирает протокол: рукопожатие с ответом на вызов сервера, запросы с
сопоставлением ответов по идентификатору и события — всё по одному соединению. Канал связи
вынесен в интерфейс `IObsTransport`, поэтому разбор протокола проверяется тестами без
запущенного OBS: в тестах его подменяет `FakeTransport`.

`ObsService` даёт приложению понятия вместо имён запросов: начать запись, остановить,
переключить профиль вместе с коллекцией сцен, развести источник по дорожке.

`ObsSetup` — перенос команды `callsum obs-setup` из питоновской версии со всеми уроками,
которые она собрала: пауза после создания коллекции сцен (иначе OBS зависает), перечитывание
профиля переключением (иначе настройки записи не применяются), поиск папки профиля по
`basic.ini` (имя папки OBS чистит от спецсимволов).
