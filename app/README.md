# Приложение на C#

Вторая версия callsum: настольное приложение, которое можно раздать коллегам без Python
и ручной настройки OBS. План и принятые решения — в [docs/plan.md](../docs/plan.md).

Сейчас готовы второй и третий этапы плана: работа с OBS и окно приложения.

| Проект | Что это |
|---|---|
| `Callsum.App` | окно на WinUI 3: кнопка записи, таймер, список готовых записей, уведомления |
| `Callsum.Core` | связь с ядром обработки: команды и события строками JSON, чтение результатов |
| `Callsum.Obs` | клиент протокола obs-websocket 5 и настройка профиля под запись созвонов |
| `Callsum.ObsTool` | консольная утилита: проверить связь и прогнать запись до того, как появится окно |
| `Callsum.Obs.Tests` | тесты протокола и разбора настроек |

## Что нужно для сборки

.NET SDK 9. Ставится в профиль пользователя, без прав администратора:

```
Invoke-WebRequest https://dot.net/v1/dotnet-install.ps1 -OutFile dotnet-install.ps1
.\dotnet-install.ps1 -Channel 9.0 -InstallDir "$env:LOCALAPPDATA\Microsoft\dotnet"
```

Дальше:

```
dotnet build app\Callsum.sln
dotnet test app\Callsum.sln
```

## Запуск окна

```
dotnet run --project app\Callsum.App
```

Окно само подключается к OBS и запускает ядро обработки, найденное рядом с собой или
в папке `dist` проекта. После остановки записи файл уходит в ядро, а окно показывает ход
работы: подготовку дорожек, распознавание с долей выполнения и составление протокола.

Окно восстанавливает связь с OBS после обрыва. Кнопка начинает и
останавливает запись; пока OBS выполняет команду, кнопка занята — он переключает профиль
и закрывает файл не мгновенно. Заголовок окна показывает, идёт ли запись.

## Список записей и уведомления

Готовые записи перечислены в окне, свежие сверху; строка говорит, есть ли протокол или
пока только расшифровка. Нажатие на строку открывает протокол, кнопка «Папка» — папку
с файлами, кнопка «Заново» — пересобирает расшифровку и протокол с нуля. Исходную запись
для этого окно берёт из `transcript.json`, куда разбор записывает полный путь к ней;
если файла там больше нет, запись ищется по имени в папке записей. Чем открывать `.md`, решает настройка `[view] markdown_app` в `config.toml`:
запись понимается так же, как в первой версии — имя программы, путь к ней, команда
с подстановкой `{file}` или ссылка вида `obsidian://open?path={file}`.

Где лежат записи и результаты, окно не угадывает: пути хранятся в настройках ядра,
поэтому при запуске оно спрашивает у ядра проверку окружения и берёт их оттуда.

Когда обработка заканчивается, Windows показывает уведомление — созвон обрабатывается
минутами, и всё это время окно обычно свёрнуто. Уведомление подписано именем `callsum`:
имя берётся из регистрации приложения (`AppUserModelID`), а без неё в подписи оказалось бы
имя исполняемого файла — в первой версии там стояло «Python».

Журнал переехал в свёрнутый раздел внизу: он нужен, когда что-то пошло не так.

## Настройки

Ссылка «Настройки» в правом верхнем углу открывает форму: папки для записей и результатов,
шаблоны имён, модель распознавания и язык, адрес и модель Ollama, чем открывать протоколы.

Файл настроек один — тот самый `config.toml`, который правят руками, — и владеет им ядро:
окно спрашивает значения командой `settings` и возвращает изменения командой `settings_set`.
Второго хранилища у приложения нет, поэтому расходиться нечему, а файл остаётся с
комментариями: ядро правит в нём отдельные значения, а не переписывает целиком.

Отправляются только изменённые поля. Если тем временем кто-то поправил файл руками, его
правки остаются на месте — окно не возвращает обратно всё, что прочитало при открытии.

Пустое значение там, где оно ничего не значит (папка, модель), не сохраняется: окно скажет,
какое поле нельзя оставлять пустым. А пустой язык и пустая программа для markdown осмысленны —
это «определять самому» и «чем открывает Windows».

Папка записей — единственная настройка, которая живёт в двух местах сразу: программа по ней
ищет записи, а OBS по своей пишет их. Поэтому при сохранении приложение задаёт её и OBS,
а при запуске сверяет обе и подтягивает при расхождении. Чужой профиль OBS не трогается:
если открыт не `callsum`, окно скажет об этом и отложит правку до возвращения в наш профиль.

Папки хранятся полными путями. Относительный путь считается от того места, откуда запущено
ядро, и в разных руках означает разные папки, а в окне «out» вообще ничего не говорит о том,
где искать протоколы. Поэтому новый `config.toml` создаётся уже с полными путями, окно
показывает их полностью, а относительный путь при сохранении не принимает. Под каждым полем
подписано, куда программа сложила бы всё сама, — видно, от чего отказываешься, выбирая свою
папку. Файл, в котором путь записан относительно, продолжает работать: при первом сохранении
из окна он превращается в полный.

### Устройства записи

Микрофон и звук системы выбираются там же, но живут они не в `config.toml`, а в коллекции
сцен OBS — вместе с источниками, которым принадлежат. Список даёт сам OBS: те же устройства
и в том же порядке, что в окне свойств источника. Недоступные (отключённая гарнитура)
в список не попадают — записать с них нечего.

Значение «По умолчанию» означает то устройство, которое выбрано в Windows. Это удобно, пока
их не несколько: у одной машины в списке оказались микрофон гарнитуры, микрофон веб-камеры
и блютус-гарнитура, и «по умолчанию» указывало не на тот, в который говорят, — запись
микрофонной дорожки выходила пустой. Поэтому устройство лучше выбрать явно.

Источники существуют в коллекции сцен `callsum`. Если в OBS открыта другая коллекция, окно
так и скажет: переключать её втихую оно не станет — это меняет то, что человек видит в OBS
прямо сейчас.

Приложение собирается **самодостаточным**: Windows App SDK едет внутри него. Иначе
неупакованное приложение WinUI требует установленной на машину среды выполнения, а её
установка просит администратора — то, чего у коллег может не быть.

## Утилита для проверки

```
dotnet run --project app\Callsum.ObsTool -- doctor
```

| Команда | Что делает |
|---|---|
| `doctor` | подключается к OBS и показывает профиль, коллекцию сцен, папку записи и источники звука |
| `setup <папка>` | создаёт профиль и коллекцию сцен `callsum`, разводит звук по дорожкам, задаёт формат записи |
| `start` / `stop` | начинает и останавливает запись; `stop` печатает путь к файлу |
| `watch` | ждёт событий записи из OBS — в том числе начатой вручную или горячей клавишей |

Пароль к websocket утилита берёт из настроек самого OBS, вводить его никуда не нужно.

## Как устроен клиент

`ObsClient` разбирает протокол: рукопожатие с ответом на вызов сервера, запросы с
сопоставлением ответов по идентификатору и события — всё по одному соединению. Канал связи
вынесен в интерфейс `IObsTransport`, поэтому разбор протокола проверяется тестами без
запущенного OBS: в тестах его подменяет `FakeTransport`.

`ObsService` даёт приложению понятия вместо имён запросов: начать запись, остановить,
переключить профиль вместе с коллекцией сцен, развести источник по дорожке.

`ObsSetup` — перенос команды `callsum obs-setup` из питоновской версии со всеми уроками,
которые она собрала: пауза после создания коллекции сцен (иначе OBS зависает), перечитывание
профиля переключением (иначе настройки записи не применяются), поиск папки профиля по
`basic.ini` (имя папки OBS чистит от спецсимволов).
