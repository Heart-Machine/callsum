# План: настольное приложение для коллег

Документ фиксирует договорённости по второй версии callsum — приложению, которое можно
раздать коллегам, не требуя от них ни Python, ни настройки OBS.

## Зачем

Текущая версия работает и отлажена, но рассчитана на разработчика: виртуальное окружение,
команды в консоли, ручная настройка OBS. Коллеге нужен установщик и окно с кнопкой.

## Итоговая архитектура

Три части, каждая занимается своим:

```
WinUI 3, C#                 ядро («мотор»)              внешние программы
┌────────────────┐  JSON   ┌──────────────────┐        ┌──────────────┐
│ окно, трей,    │ ──────► │ callsum-core.exe │ ─────► │ ffmpeg       │
│ настройки,     │ ◄────── │ (текущий Python, │ ─────► │ Ollama       │
│ управление OBS │ события │  собран в exe)   │        └──────────────┘
└────────┬───────┘         └──────────────────┘
         │ obs-websocket
         ▼
    ┌─────────┐
    │   OBS   │
    └─────────┘
```

Приложение отвечает за то, что видит пользователь, и за запись; мотор — за обработку.
Граница проходит там же, где сейчас проходит граница между `gui.py` и `pipeline.py`.

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Интерфейс | WinUI 3, C# на .NET 9 | основной язык Windows App SDK, весь тулинг под него |
| Запись | остаётся OBS, управляемый из приложения | синхронизация двух дорожек уже решена, запись экрана достаётся почти даром |
| Распознавание | `faster-whisper` в отдельном процессе | проверенная скорость (x12–23) и пословные таймкоды; переписывать нечего |
| Протокол созвона | локальная Ollama | у всех коллег есть видеокарта NVIDIA |
| Провайдер LLM | за интерфейсом, с прицелом на облачные | облако появится настройкой, а не переделкой |
| Установка | в профиль пользователя, без администратора | нет сертификата подписи, нужны тихие обновления |
| Обновления | Velopack + GitHub Releases | обновляется внутри процесса, SmartScreen беспокоит только при первой установке |

## Договор между приложением и мотором

Мотор запускается один раз и живёт, пока открыто приложение: модель распознавания грузится
в видеопамять секунды, и на каждый файл её перезагружать нельзя. Обмен — построчный JSON:
команды в стандартный ввод, события в стандартный вывод, журнал в поток ошибок.

Команды:

```json
{"cmd": "process",   "id": "1", "path": "D:/recordings/2026-09-12 14-03-11.mkv", "force": false}
{"cmd": "summarize", "id": "2", "transcript": "D:/out/созвон/transcript.md"}
{"cmd": "doctor",    "id": "3"}
{"cmd": "settings",  "id": "4"}
{"cmd": "settings_set", "id": "5", "values": {"paths": {"out": "D:/созвоны"}}}
{"cmd": "shutdown"}
```

События:

```json
{"event": "progress", "id": "1", "stage": "transcribe", "fraction": 0.42, "detail": "Собеседник"}
{"event": "log",      "id": "1", "text": "дорожка 2 (Собеседник) пустая — пропускаю"}
{"event": "done",     "id": "1", "out_dir": "D:/out/созвон", "summary": true}
{"event": "error",    "id": "1", "message": "Все дорожки пустые — распознавать нечего"}
{"event": "ready",    "device": "cuda", "compute_type": "float16"}
{"event": "settings", "id": "4", "path": "…/config.toml", "values": {}, "resolved": {}}
```

Настройки живут в одном файле — `config.toml`, — и владеет им ядро: оно и так читает его
при каждом запуске, знает умолчания и умеет проверять значения. Приложение получает их
командой `settings`, показывает форму и возвращает изменения; ядро правит файл по одному
значению, сохраняя комментарии, и перечитывает себя. Второго хранилища настроек, своего
у приложения, нет — расходиться было бы нечему.

Стадии те же, что сейчас: `audio`, `transcribe`, `summary`, `done`. Это ровно тот набор,
который уже отдаёт `pipeline.process`, так что на стороне Python добавляется только команда
`serve` — цикл чтения команд и печать событий.

## Этапы

| № | Этап | Оценка |
|---|---|---|
| 1 | Команда `serve` в ядре, сборка в exe через PyInstaller, включая библиотеки CUDA | 2 дня |
| 2 | Клиент obs-websocket на C# и перенос автонастройки профиля | 1–1,5 дня |
| 3 | Интерфейс WinUI 3: кнопка, таймер, прогресс, список записей, уведомления | 3–4 дня |
| 4 | Настройки: папки, шаблоны имён, провайдер LLM и модель, устройства | 1–2 дня |
| 5 | Velopack, публикация в GitHub Releases, докачка модели при первом запуске | 1–2 дня |
| 6 | Пилот на двух коллегах | 1 день + отзывы |

Итого 9–12 рабочих дней. Технических неизвестных не осталось: распознавание, разметка по
говорящим и протоколы уже работают и проверены на реальных записях.

## Что коллега делает руками

1. Ставит OBS (одна команда `winget install OBSProject.OBSStudio` или установщик с сайта).
2. Включает в OBS websocket-сервер — одна галочка в «Сервис» → «Настройки сервера WebSocket».
3. Ставит FFmpeg: `winget install Gyan.FFmpeg`. В установщик он не входит — им извлекаются
   дорожки из записи, и без него не обработать ничего.
4. Ставит Ollama и модель — около 9 ГБ.
5. Запускает установщик callsum и один раз соглашается с предупреждением SmartScreen.
6. В окне callsum нажимает «Настроить OBS» — программа сама предложит, когда увидит,
   что профиля ещё нет.

Всё остальное приложение делает само: создаёт профиль и коллекцию сцен, разводит дорожки,
задаёт формат записи, скачивает библиотеки видеокарты и модель распознавания. О том, что
из этого списка ещё не сделано, оно говорит плашками в главном окне — с командой, которую
нужно выполнить.

## Раскладка файлов на машине пользователя

| Что | Куда | Почему |
|---|---|---|
| Программа и мотор | `%LOCALAPPDATA%\callsum` | без прав администратора, обновляется целиком |
| Настройки | `%APPDATA%\callsum\config.toml` | переживают обновление и переустановку |
| Модель распознавания | `%LOCALAPPDATA%\callsum-data\models` | не в папке программы: иначе перекачивалась бы при каждом обновлении |
| Библиотеки CUDA | `%LOCALAPPDATA%\callsum-data\cuda` | около двух гигабайт: в установщик не влезают (предел файла в релизе — 2 ГБ), скачиваются при первом распознавании |
| Записи и результаты | `%USERPROFILE%\callsum` либо папка по выбору | пользовательские данные |

Папка программы — `%LOCALAPPDATA%\callsum`, и распоряжается ею установщик: при установке он
её очищает. Поэтому всё скачанное лежит рядом, в `callsum-data`, а не внутри. Проверено
дорого: первая установка унесла оттуда два гигабайта уже скачанных библиотек.

## Отложено намеренно

- **Запись экрана.** С OBS это источник в профиле и больший холст — настройка, не разработка.
- **Облачные модели для протокола.** Интерфейс провайдера закладывается сразу, реализация — позже.
  Важно помнить: с появлением облака «всё считается на этой машине» перестаёт быть свойством
  программы и становится настройкой, и это решение нужно согласовать.
- **Видеокарты AMD и Intel.** Все коллеги на NVIDIA. Если появится потребность, есть готовый путь:
  Whisper.net с Vulkan как вторая реализация того же интерфейса.
- **Общий сервер обработки.** Обмен с мотором описан так, что его можно вынести на машину
  с видеокартой, заменив трубы на HTTP.

## Судьба текущей версии

Питоновская версия остаётся рабочей и служит эталоном: на одной и той же записи сверяем
расшифровку и протокол. Командная строка (`callsum process`, `watch`, `summarize`, `doctor`)
никуда не девается — ядро используется и приложением, и напрямую.
