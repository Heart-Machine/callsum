# callsum — локальная расшифровка и протоколы созвонов

Полностью офлайн-пайплайн: запись созвона (OBS) → расшифровка (faster-whisper large-v3 на GPU)
→ протокол с решениями и задачами (Qwen3 14B через Ollama) → файлы в папке `out`.

Никакие данные наружу не уходят: всё считается на этой машине.

## Из чего собрано

| Компонент | Где | Назначение |
|---|---|---|
| Python 3.11 + venv | `.venv` | окружение проекта |
| faster-whisper 1.2 + CTranslate2 4.8 (CUDA) | `.venv` | распознавание речи на GPU |
| Ollama + `qwen3:14b` (Q4, ~9 ГБ) | системно, порт 11434 | саммари |
| FFmpeg | системно | разбор аудиодорожек |
| PySide6 + websocket-client | `.venv` | окно, значок в трее, свой клиент obs-websocket |
| OBS Studio 32 | системно | запись звука; профиль `callsum` с двумя дорожками |

## Установка

Нужны Windows, видеокарта NVIDIA (без неё распознавание пойдёт на процессоре — медленно),
[Python 3.11](https://www.python.org/downloads/), [FFmpeg](https://www.gyan.dev/ffmpeg/builds/),
[OBS Studio](https://obsproject.com/) 28 или новее и [Ollama](https://ollama.com/).

```
git clone https://github.com/Heart-Machine/callsum.git
cd callsum
py -3.11 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Затем модель для протоколов (около 9 ГБ, под 12 ГБ видеопамяти):

```
ollama pull qwen3:14b
```

Модель распознавания `large-v3` (около 3 ГБ) скачается сама при первом запуске.
Файл настроек тоже: при первом запуске любой команды рядом с `config.example.toml`
появится ваш `config.toml` — его и правьте. В репозиторий он не попадает, так что личные
пути, выбранная модель и любимый редактор остаются только у вас.

Включите в OBS WebSocket-сервер («Инструменты» → «Настройки WebSocket-сервера» → галочка)
и настройте профиль под запись созвонов:

```
callsum obs-setup
```

Проверка, что всё на месте:

```
callsum doctor
```

## Приложение: одна кнопка

```
callsum-gui.cmd
```

Окно с большой кнопкой «Начать запись» и значком в трее. Что происходит по нажатию:

1. OBS переключается на профиль `callsum` (ваш прежний профиль запоминается и возвращается
   после остановки) и начинает запись двух дорожек.
2. В окне идёт таймер, значок в трее становится красным.
3. По кнопке «Остановить» OBS заканчивает запись и сообщает приложению путь к файлу —
   обработка начинается сразу, с полосой прогресса по стадиям (дорожки → распознавание →
   протокол). Пока OBS выполняет команду, кнопка недоступна и показывает «Останавливаю…»:
   переключение профиля и закрытие файла занимают секунду-другую, и по кнопке успевали
   нажать несколько раз.
4. Когда всё готово, выскакивает уведомление, а созвон появляется в списке: кнопки
   «Протокол», «Расшифровка», «Папка» открывают результат.

Окно можно закрыть крестиком — приложение свернётся в трей и продолжит работу; запись
и обработка управляются из меню значка. Выход — «Выход» в том же меню.

Уведомления приходят от имени «callsum»: приложение регистрирует себя в Windows
(`HKCU\Software\Classes\AppUserModelId\Callsum.CallRecorder`) и шлёт системные
уведомления, а не подсказки из трея — те подписываются именем процесса, и в заголовке
получалось «Python». Значок для них сохраняется в `%LOCALAPPDATA%\callsum`. Убрать
регистрацию, если она не нужна: `reg delete "HKCU\Software\Classes\AppUserModelId\Callsum.CallRecorder" /f`.

Кнопка «Обработать файл…» прогоняет через пайплайн любую готовую запись, в том числе
сделанную не в OBS.

Приложение запускается в одном экземпляре: повторный запуск просто покажет уже открытое
окно. Иначе два окна подписались бы на события OBS одновременно и взялись бы обрабатывать
одну запись вдвоём, деля видеопамять с Ollama. По той же причине запись, для которой
расшифровка уже есть, повторно не обрабатывается — кроме явной просьбы через
«Обработать файл…».

Модель распознавания загружается в видеопамять при первой обработке и остаётся там
до выхода из приложения, поэтому второй и последующие созвоны начинают обрабатываться сразу.

Хотите запускать по горячей клавише — назначьте её в самом OBS («Настройки → Горячие
клавиши → Начать запись»): приложение видит запись, начатую любым способом, и обработает
файл так же.

### Автозапуск вместе с Windows

Положите ярлык на `callsum-gui.cmd` в папку автозагрузки: `Win+R` → `shell:startup`.

## Настройка OBS

Всё делает одна команда — она создаёт **отдельный** профиль и коллекцию сцен `callsum`
и не трогает те, которыми вы пользуетесь для остального:

```
callsum obs-setup
```

Что она настраивает:

| Что | Значение | Зачем |
|---|---|---|
| Режим вывода | Расширенный | только он умеет несколько аудиодорожек |
| Формат записи | mkv | не бьётся, если запись оборвётся |
| Дорожки | 1 и 2 | микрофон и звук системы раздельно |
| Папка записи | `recordings` проекта | оттуда же работает `callsum watch` |
| Имя файла | `%CCYY-%MM-%DD %hh-%mm-%ss` | шаблон настраивается, см. `[obs] filename_format` |
| Микрофон | дорожка 1 | это «Я» в расшифровке |
| Звук системы | дорожка 2 | это «Собеседник» |
| Холст | 640×360, 10 к/с, x264 CRF 32 | картинка не нужна: час записи ≈ 75 МБ |

Разделение «я / собеседник» делается именно так — на уровне записи, а не нейросетевой
диаризацией. Поэтому оно работает с любым приложением (Zoom, Meet, Telegram, Teams,
браузер) и не путает, кто что сказал.

Требуется включённый WebSocket-сервер OBS: «Инструменты» → «Настройки WebSocket-сервера» →
галочка «Включить WebSocket-сервер». Пароль приложение берёт из настроек самого OBS,
вводить его никуда не нужно.

Если несколько внешних участников — все они попадут в дорожку `Собеседник`: системный звук
физически один. Различить их внутри дорожки пайплайн не пытается — по опыту это даёт больше
путаницы, чем пользы.

### Если настраивать руками

«Настройки → Вывод → Расширенный → Запись»: формат mkv, отметить дорожки 1 и 2, путь —
папка `recordings`. Затем в микшере: шестерёнка у источника → «Расширенные свойства аудио»
→ у микрофона оставить галочку только на дорожке 1, у звука системы — только на дорожке 2.
Последний шаг ключевой: по умолчанию OBS шлёт оба источника на все дорожки, и разделения
по говорящим не будет.

## Работа без окна

Записали созвон в OBS → файл лёг в `recordings` → дальше либо вручную:

```
callsum process "recordings\2026-09-12 14-03-11 созвон.mkv"
```

либо один раз запустить слежение за папкой и забыть про команды:

```
callsum watch
```

`watch` сам дожидается, когда OBS допишет файл (размер не меняется 20 секунд), обрабатывает
запись и кладёт результат в `out\<имя файла>\`:

```
out\2026-09-12 14-03-11 созвон\
  transcript.md    расшифровка диалога с таймкодами и разметкой по говорящим
  transcript.srt   субтитры (можно смотреть запись с текстом)
  transcript.json  сегменты с таймкодами — для своей автоматизации
  summary.md       протокол: кратко, темы, решения, задачи, открытые вопросы, следующие шаги
```

### Все команды

| Команда | Что делает |
|---|---|
| `callsum gui` | окно с кнопкой записи и значком в трее (то же, что `callsum-gui.cmd`) |
| `callsum obs-setup` | создать в OBS отдельный профиль под запись созвонов |
| `callsum process <файл\|папка> [--force]` | обработать запись или всю папку |
| `callsum process ... --no-summary` | только расшифровка, без обращения к LLM |
| `callsum process ... --keep-audio` | оставить извлечённые WAV-дорожки рядом с результатом |
| `callsum watch [--once]` | следить за папкой записей; `--once` — один проход |
| `callsum summarize out\<созвон>` | пересобрать протокол по готовой расшифровке |
| `callsum doctor` | проверить FFmpeg, GPU, Ollama, модель и связь с OBS |

Вместо `callsum` можно звать `.venv\Scripts\python.exe -m callsum` — `callsum.cmd` это просто обёртка.

## Ядро для настольного приложения

Готовится вторая версия — приложение на WinUI 3 ([docs/plan.md](docs/plan.md)). Обработкой
в ней занимается это же ядро, запущенное отдельным процессом: команды приходят строками
JSON в стандартный ввод, события уходят в стандартный вывод.

```
callsum serve
```

Команды — `process`, `summarize`, `doctor`, `shutdown`; события — `ready`, `progress`, `log`,
`done`, `error`. Полное описание с примерами — в начале [callsum/serve.py](callsum/serve.py)
и в [плане](docs/plan.md). Модель распознавания грузится один раз и живёт, пока живёт
процесс, поэтому второй и последующие созвоны начинают обрабатываться сразу.

Проверить руками можно так — ядро ответит на команду и завершится:

```
echo {"cmd": "doctor", "id": "1"} | callsum.cmd serve
```

### Сборка ядра в exe

```
packaginguild-core.cmd
```

Результат — папка `dist\callsum-core` с `callsum-core.exe`, около 2,2 ГБ. Почти всё это —
библиотеки CUDA: без них распознавание пошло бы на процессоре. Собирается папкой, а не одним
файлом: запуск быстрее, а обновления передают только изменившиеся файлы, и эти гигабайты
не перекачиваются с каждой версией. Для сборки нужен PyInstaller:
`pip install -r requirements-dev.txt`.

Настройки собранное ядро держит в профиле пользователя — `%APPDATA%\callsum\config.toml`,
а записи и результаты по умолчанию складывает в `%USERPROFILE%\callsum`. Внутри папки
программы им не место: обновление ставится поверх неё, и всё, что там лежало, пропадает.
«Документы» не выбраны намеренно — на многих машинах они перенаправлены в OneDrive, и
записи разговоров молча уезжали бы в облако. Настройки прежней версии, лежавшие рядом
с `callsum-core.exe`, при первом запуске переносятся сами.

При запуске из исходников ничего не меняется: `config.toml`, `recordings` и `out` берутся
из папки проекта. Промпты и пример настроек лежат внутри сборки.

## Настройка

Всё в `config.toml` (создаётся из `config.example.toml` при первом запуске), основное:

- `[transcribe] model` — `large-v3` (точнее) или `medium` / `small` (быстрее).
- `[transcribe] language` — `"ru"`. Пусто = автоопределение (нужно для созвонов на английском).
- `[summary] model` — модель Ollama. `qwen3:14b` выбрана под 12 ГБ VRAM.
- `[summary] num_ctx` — окно контекста. При 8192 модель `qwen3:14b` целиком помещается
  в 12 ГБ видеопамяти; при 16384 она занимает 12 ГБ, часть слоёв Ollama считает на
  процессоре, и протокол готовится примерно вдвое дольше (замер на одном и том же
  созвоне: 13,8 с против 32,4 с). Если видеопамяти больше 12 ГБ — значение можно поднять,
  тогда длинные созвоны пойдут меньшим числом проходов. Транскрипты длиннее `chunk_chars`
  режутся на части автоматически и сводятся в один протокол.
- `[summary] enabled = false` — выключить LLM совсем, оставить только расшифровки.
- `[summary] keep_alive` — сколько модель держится в видеопамяти после ответа. По умолчанию
  `"0s"`: выгружать сразу, чтобы распознавание следующего созвона получило всю карту.
  Если видеопамяти много, поставьте `"5m"` — тогда подряд идущие протоколы не будут
  тратить несколько секунд на загрузку модели.
- `[view] markdown_app` — чем открывать протоколы по кнопкам в окне. Пусто — системная
  ассоциация `.md`; если её нет, Windows спросит «чем открыть». Примеры значений:
  `"notepad++"`, `'C:\Program Files\Typora\Typora.exe'`, `"code -r {file}"`,
  `"obsidian://open?path={file}"`. Подстановка `{file}` необязательна: без неё файл
  просто добавляется последним аргументом. Путь Windows записывайте в **одинарных**
  кавычках: в двойных TOML считает обратный слеш началом escape-последовательности,
  и его пришлось бы удваивать. Если конфиг всё же не разберётся, приложение покажет
  окно с объяснением, а не промолчит.
- `[obs] profile` — имя профиля и коллекции сцен OBS, на которые переключаться перед записью;
  `auto_switch = false` отключает переключение, `restore_after = false` — возврат прежнего профиля.
- `[obs] filename_format` — как OBS называет файлы записей. Синтаксис OBS: `%CCYY` год,
  `%MM` месяц, `%DD` день, `%hh` часы, `%mm` минуты, `%ss` секунды. Применяется командой
  `callsum obs-setup` — после правки запустите её ещё раз.
- `[paths] folder_template` — как называется папка одного созвона внутри `out`. Подстановки:
  `{name}` — имя файла записи, `{date}` — ГГГГ-ММ-ДД, `{time}` — ЧЧ-ММ-СС, `{datetime}` — то и
  другое. По умолчанию `"{name}"`, то есть папка называется так же, как файл записи.

Параметры, которых нет в вашем `config.toml`, берутся из значений по умолчанию в коде —
после обновления проекта старый файл продолжит работать, а новые возможности включатся
сами. Свежие параметры с комментариями всегда можно подсмотреть в `config.example.toml`.

Шаблон протокола — обычный текстовый файл `prompts/summary_ru.md`, правьте под себя.
Там же `map_ru.md` и `reduce_ru.md` — они используются для длинных созвонов (больше ~2.5 часов).

## Производительность

Замерено на этой машине (RTX 5070, 12 ГБ) на тестовом созвоне из двух дорожек:
распознавание идёт со скоростью **x12–x23 от реального времени**, то есть часовой созвон
с двумя дорожками — это примерно 5–10 минут на обе дорожки. Протокол на коротком созвоне
занял полторы минуты, из которых большая часть — первая загрузка модели в видеопамять.

Распознавание и языковая модель делят одну видеокарту, и вместе в 12 ГБ они не помещаются:
`qwen3:14b` занимает около 10 ГБ, модель распознавания — ещё несколько. Если обе остаются
в видеопамяти, Windows начинает возить данные через обычную память, и протокол готовится
в десятки раз дольше (замеренный случай: 18 минут вместо 15 секунд). Поэтому программа
освобождает карту сама: перед составлением протокола выгружает модель распознавания,
а Ollama просит выгрузить языковую модель сразу после ответа (`[summary] keep_alive`).
Полный прогон двухминутного созвона после этого занимает около 37 секунд.
Пример готовых файлов лежит в папке `examples` — это синтетический созвон, на котором
пайплайн проверялся.

## Если что-то сломалось

- `callsum doctor` — первая команда при любой проблеме.
- **GPU не виден / ошибка cudnn** — пайплайн сам откатится на CPU (медленно). Проверить:
  `.venv\Scripts\python.exe -c "import ctranslate2; print(ctranslate2.get_cuda_device_count())"`.
- **Ollama не отвечает** — запустить приложение Ollama или `ollama serve`; расшифровка при
  этом всё равно сохраняется, протокол потом добирается командой `callsum summarize`.
- **OBS закрыли при работающем окне** — в шапке появится «OBS: нет подключения, пробую
  подключиться…», кнопка записи станет серой. Закрывать приложение не нужно: как только OBS
  снова запустится, связь восстановится сама и кнопка оживёт.
- **В расшифровке один говорящий вместо двух** — не разведены дорожки в «Расширенных
  свойствах аудио» OBS — проще всего выполнить `callsum obs-setup`. Проверить дорожки в файле:
  `ffprobe -v error -select_streams a -show_entries stream=index:stream_tags=title -of json запись.mkv`.
